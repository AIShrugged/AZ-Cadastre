# Shape: приведение репозитория к правилам модульного монолита

Временный файл. Удаляется последним шагом вместе с постановкой ADR-0007.

Порядок шагов — из `workflow/shape.md`: границы → контракты → слои → порты →
тесты → стиль → документы. Один шаг — один коммит. После каждого: `pnpm lint`,
`pnpm -r typecheck`, `pnpm test`.

Разведка показала, что репозиторий уже выполняет правила 3, 4, 6 (по сути), 7, 8,
9, 10, 11, 13. Ниже — только расстояние, которое осталось.

---

## 1. Границы: CI и ссылки на ADR в сообщениях линтера

**Зачем.** Сегодня правила держит только husky-хук, а `git commit --no-verify`
снимает его целиком — то есть граница не обеспечена ничем, что переживёт спешку.
`boundaries.md` требует от сообщения линтера трёх вещей: назвать правило, назвать
выход и сослаться на ADR. Сейчас есть первые две.

**Готово, когда.** Есть `.github/workflows/ci.yml`, гоняющий lint, typecheck,
build и тесты на push и pull request; каждое сообщение `no-restricted-imports`
ссылается на ADR-0006.

## 2. Контракты: `sideEffects: false`

**Зачем.** `@cadastre/api-contracts` уходит в браузерный бандл `apps/web`. Без
объявления пакет считается имеющим побочные эффекты, и tree-shaking выключается:
клиент тащит схемы всех операций ради одной.

**Готово, когда.** Поле есть в `libs/api-contracts/package.json`; сборка web
проходит.

## 3. Порт репозитория переезжает в прикладной слой

**Зачем.** `VerificationPackageRepository` лежит в `domain/repositories/` —
прямое нарушение правила 6 конституции. Порт принадлежит `application/ports`,
потому что намерение «сохранить агрегат» формулирует сценарий, а не модель.

**Готово, когда.** Файл — `application/ports/outbound/verification-package-repository.port.ts`,
папки `domain/repositories/` нет, модуль и адаптер импортируют из нового места.

## 4. Адаптеры называются адаптерами

**Зачем.** Таблица имён из `style.md`: реализация порта — `*-repository.adapter.ts`
с классом `…RepositoryAdapter`. Сейчас реализация зовётся так же, как порт
(`verification-package.repository.ts`), а `package-queries.adapter.ts` содержит
класс `PrismaPackageQueries`. Суффикс рода — то, по чему файл находят не открывая.

**Готово, когда.** `verification-package-repository.adapter.ts` →
`VerificationPackageRepositoryAdapter`, `package-queries.adapter.ts` →
`PackageQueriesAdapter`. Переименование — отдельным `git mv`-коммитом от правок.

## 5. Чистый расчёт уходит из инфраструктуры

**Зачем.** `infrastructure/adapters/` — плоская папка на 20 файлов, где семь
из них не адаптеры, а чистые правила предметной области: совпадают ли два
значения с двух бумаг (`value-agreement`), есть ли цитата модели в тексте
(`evidence`), на какой тип похож текст по заголовкам профиля (`hint-matching`),
как разложить начала документов в покрывающие диапазоны (`page-range-tiling`), и
словарь пометок расшифровки (`transcription-marks`). Они ничего не импортируют,
кроме доменных value objects, и покрыты unit-тестами — то есть уже живут по
правилам домена, просто не в той папке. Правило 14: тест живёт там, где
сломалось; сейчас домен ломается в `infrastructure/`.

`answered.ts`, `logprob-confidence.ts` и `pdf-page-renderer.ts` остаются
инфраструктурой — они знают типы OpenAI SDK и pdfjs.

**Готово, когда.** `domain/services/` содержит четыре чистых правила со своими
спеками, `domain/constants/transcription-marks.ts` — словарь; специфика
OpenRouter лежит в `infrastructure/adapters/openrouter/`; линтер по-прежнему не
видит в `domain/` ни одного инфраструктурного импорта.

## 6. Барели несут провайдеров

**Зачем.** `style.md`: барель `infrastructure/persistence/index.ts` — массив
провайдеров со связыванием портов, а не список реэкспортов. Сегодня все 20
связываний свалены в `verification.module.ts`, и он на 160 строк — читать в нём
нечего, кроме проводки.

**Готово, когда.** Связывание живёт рядом с реализациями (`persistence`,
`adapters`, `identity`, `use-cases`, `services`), модуль собирается из массивов.

## 7. Мапперы называются мапперами

**Зачем.** `*.presenter.ts` — имя не из таблицы. Внутри уже правильные чистые
`toXDto`, менять нечего, кроме имени файла и места.

**Готово, когда.** `application/use-cases/<группа>/<сущность>.mapper.ts`.

## 8. Операции читаются одинаково

**Зачем.** `style.md`: `findOne` / `findMany` / `create` во всём репозитории.
Сейчас `PackagesApi` и `ProfilesApi` объявляют `list` рядом с `findOne` — разнобой
в опубликованном языке, то есть в том, что дороже всего менять потом.

**Готово, когда.** `list` → `findMany` в контрактах, шлюзе и `apps/web`;
HTTP-пути не тронуты.

## 9. Файл на род

**Зачем.** 11 доменных событий в одном файле, 4 идентификатора в одном, 40
исключений в шести. Таблица имён требует `*.event.ts`, `*-id.vo.ts`,
`*.exception.ts` — по ним файл находят поиском, и по ним же пишутся правила.

**Готово, когда.** `domain/events/*.event.ts`,
`domain/value-objects/entity-ids/*.vo.ts`, `domain/exceptions/*.exception.ts`;
бареля реэкспортируют; ни один импорт снаружи домена не изменился.

## 10. Ссылки проектов и `composite`

**Зачем.** `architecture.md`: пакет собирается своим `tsc -p tsconfig.build.json` в
режиме `composite`, ссылки — в корневом `tsconfig.json`. Сейчас ни `composite`, ни
`references` нет, поэтому пересборка пакета не знает, что устарело ниже по графу,
и `nx` держит корректность в одиночку.

**Готово, когда.** `composite: true` в каждом `tsconfig.build.json`, `references`
в корневом, `pnpm build` с нуля проходит.

## 11. Интеграционный набор тестов

**Зачем.** Главная дыра. Prisma-маппер, репозиторий, история миграций и проводка
Nest не проверяются ничем: unit-тесты домена их не видят по определению, а других
наборов нет. Схема базы не проверяется моками — только настоящей базой
(`testing.md`).

**Готово, когда.** Postgres в testcontainers поднимается один раз на набор,
миграции накатываются, модуль контекста собирается с заглушками внешних портов
(OCR, классификатор, сегментатор, экстрактор, кросс-чекер, хранилище), тест ходит
через `commandBus`/`queryBus`, а не через сервисы. Отдельная
`vitest.integration.config.ts`, команда `test:integration`, набор гоняется в CI.

## 12. Документы

**Зачем.** Нет `AGENTS.md` (как здесь работать и куда не наступать) и нет
`TECH_DEBT.md` — то есть сознательные компромиссы не записаны нигде, и следующий
читатель примет их за баги.

**Готово, когда.** Есть `AGENTS.md` с симлинком `CLAUDE.md`, есть `TECH_DEBT.md`
со сценариями отказа, ADR-0007 фиксирует принятые отступления (один пакет
контрактов на все контексты, отсутствие outbox, `packages/` вместо `contexts/`),
`CONTEXT-MAP.md` обновлён, этот файл удалён.
